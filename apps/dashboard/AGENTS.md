# Dashboard Agent Guide

هذه الوثيقة مخصصة لوكلاء الذكاء الاصطناعي والمطورين الذين يعملون داخل
`apps/dashboard`. يجب اعتبارها مرجعًا مختصرًا قبل تعديل أي ملف في هذا التطبيق.

## نطاق التطبيق

لوحة التحكم هي تطبيق React يعمل بواسطة Vite، وتستخدم:

- React 19 وTypeScript.
- React Router للمسارات والتحميل الكسول للصفحات.
- TanStack Query لجلب البيانات وتنفيذ mutations.
- Axios للاتصال بالـ API.
- Zustand للحالة العامة.
- Tailwind CSS ومكونات UI المشتركة.
- `sonner` لإشعارات النجاح والأخطاء.

واجهة التطبيق عربية وتعمل باتجاه RTL. حافظ على النصوص العربية واتجاه
`dir="rtl"` عند إضافة أو تعديل واجهات المستخدم.

## خريطة المجلدات

```text
src/
├── feature/       # صفحات ومميزات المنتج
├── api/           # API hooks والطلبات والأنواع والتحويلات
├── components/    # مكونات مشتركة داخل dashboard
├── routes/        # تعريف المسارات والتحميل الكسول
├── layout/        # التخطيط العام للتطبيق
├── middlewares/   # المصادقة واستعادة المستخدم
├── store/         # Zustand stores
├── hooks/         # React hooks المشتركة
├── enum/          # القيم المحددة والأنواع المرتبطة بها
└── lib/            # الأدوات والثوابت والإعدادات
```

## قواعد تنظيم الميزة

ضع كل منطق مرتبط بميزة داخل `src/feature/<feature-name>`. استخدم الشكل
التالي عند الحاجة:

```text
feature/<feature-name>/
├── index.tsx       # نقطة دخول الصفحة
├── components/     # مكونات خاصة بالميزة
├── helper.tsx      # أعمدة الجداول والدوال المساعدة
└── type.ts         # أنواع واجهة الميزة
```

- أضف طلبات البيانات داخل `src/api/<domain>`.
- افصل أنواع استجابة الـ API عن أنواع واجهة المستخدم عند الحاجة.
- استخدم `transform.ts` لتحويل بيانات الـ API إلى الشكل الذي تحتاجه الواجهة.
- اربط الصفحة في `src/routes/index.tsx` باستخدام `lazy` مثل المسارات الحالية.
- أضف عنصر القائمة في `src/components/sidebar/sidebar-config.tsx`.
- لا تنقل منطق ميزة إلى `components/` العامة إلا إذا كان قابلًا لإعادة
  الاستخدام فعلًا.

## نمط API والبيانات

عند إضافة domain جديد، اتبع النمط الموجود في `src/api/course`:

- `api.ts`: دوال الطلب وTanStack Query hooks.
- `type.ts`: أنواع الطلبات والاستجابات.
- `transform.ts`: تحويل البيانات عند الحاجة.
- `index.ts`: التصدير العام عند استخدامه في هذا الـ domain.

التزم بما يلي:

- استخدم `api` من `src/api/instance.ts` بدل إنشاء Axios instance جديد.
- عرّف `queryKey` ثابتًا لكل resource.
- بعد نجاح create/update/delete، قم بإبطال query المرتبطة.
- استخدم رسائل `toast` واضحة باللغة العربية.
- أظهر حالة التحميل والخطأ بدل إرجاع واجهة نجاح وهمية.
- لا تضع عناوين API أو الأسرار داخل الكود؛ استخدم إعدادات البيئة الحالية.

## أسلوب الكود

- استخدم TypeScript بصرامة وتجنب `any` وعمليات التحويل غير الضرورية.
- استخدم alias الاستيراد `@/` من `src` بدل المسارات النسبية الطويلة.
- حافظ على تنسيق الملفات الحالي؛ يستخدم المشروع Prettier وESLint.
- استخدم أسماء واضحة ومتوافقة مع الملفات الموجودة.
- اجعل المكونات صغيرة، واستخرج النماذج والمكونات المتخصصة إلى
  `feature/<name>/components`.
- استخدم مكونات UI الموجودة قبل إنشاء مكون مشابه جديد.
- لا تعدل الحزم أو إعدادات monorepo إذا كان التغيير خاصًا بالـ dashboard فقط.
- لا تغيّر سلوك الصلاحيات أو المصادقة دون مراجعة تدفق
  `middlewares/` و`store/user.store.ts`.

## المسارات والحالة

- المسارات الرئيسية معرفة في `src/routes/index.tsx`.
- الصفحة الرئيسية هي `feature/panel`.
- المستخدم الحالي محفوظ عبر Zustand في `src/store/user.store.ts`.
- صلاحية `admin` تتحكم في بعض المسارات وعناصر القائمة.
- استخدم `AppSheet` و`AppDialog` من الـ stores الحالية للنماذج والإجراءات
  التي تتبع نمط التطبيق.

## أوامر التحقق

نفّذ الأوامر من جذر المستودع:

```bash
pnpm --filter ces-platform-dashboard dev
pnpm --filter ces-platform-dashboard lint
pnpm --filter ces-platform-dashboard build
```

وعند تغيير كود مشترك أو إعدادات على مستوى المستودع، شغّل أيضًا:

```bash
pnpm lint
pnpm check-types
pnpm build
```

لا تعتبر المهمة مكتملة قبل تشغيل أصغر مجموعة أوامر تغطي التغيير. إذا فشل
أمر بسبب مشكلة موجودة مسبقًا، اذكر الخطأ بوضوح ولا تتجاهله.

## قائمة مراجعة قبل إنهاء المهمة

- هل وضعت الكود في الميزة أو الـ domain الصحيح؟
- هل حافظت على RTL والنصوص العربية؟
- هل أضفت حالات loading وerror وempty عند الحاجة؟
- هل تم تحديث query cache بعد mutation؟
- هل تم ربط المسار والقائمة الجانبية؟
- هل أضفت أو حدّثت الأنواع بدل استخدام `any`؟
- هل شغلت lint وbuild المناسبين؟
- هل التغيير محدود بالطلب ولا يحتوي على إعادة هيكلة غير مطلوبة؟
